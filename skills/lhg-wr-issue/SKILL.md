# lhg-wr-issue：问题写法"现象+根因+对策"

> 目标：让"问题与风险"章节成为解题的开始，而不是告状的结束。核心纪律：**只写现象不给对策=告状，只给对策不写根因=拍脑袋**。
> 适用对象：周报"问题与风险"章节、项目复盘、风险预警。
> 前置：卡点清单已收齐（延期、阻塞、异常数据、依赖风险）。

## 1. 何时使用

- 写"问题与风险"的每一条 → 逐条套用三段式
- 用户只说了现象（"联调 blocked"）→ 用第 4 步挖根因、配对策
- 本周真没问题 → 写"风险前瞻"（见第 6 步）

## 2. 三段式

```
现象：活动页转化率环比下降 0.6 个百分点（3.8%→3.2%）
根因：预热页首屏 CTA 按钮在小屏手机上被折叠，用户看不到行动入口
对策：周二前改一版首屏布局并做 A/B 验证（已排进下周计划）
```

**三段缺一不可**：
- 只有现象→老板："所以呢？要我做什么？"
- 现象+对策（无根因）→对策可能是错的（CTA 被折叠，你却去改了文案）
- 现象+根因（无对策）→等于把问题抛给老板

## 3. 现象怎么写

- **可观测**：用数字或事实描述，不用感受。"转化率下降 0.6 个百分点"是现象，"转化率有点问题"是感受。
- **定位**：现象要定位到具体环节。"联调阻塞"不够，"联调环境数据库被占满，阻塞 6 小时"才够。
- **分级**：每个问题标影响——🔴 阻塞主线 / 🟡 有风险但可控 / 🟢 已解决（复盘用）。周报里🔴不超过 2 个，超过说明这周基本在救火，要单独说明。

## 4. 根因怎么挖：连问三次"为什么"

```
现象：联调环境阻塞 6 小时
为什么1：测试环境数据库被其他团队任务占满
为什么2：没有独立的 schema，多团队共用一套环境
为什么3：环境申请流程没走，一直在"临时借用"
根因：环境资源未独立 + 申请流程缺失
对策：已申请独立 schema，周三前迁移；同时补走环境申请流程
```

**根因铁律**：
- 根因不许是"人"（"因为小王没做好"）——要写成系统/流程问题（"因为缺少 code review 环节"）。对人不对事的问题，进周报就是告状。
- 问到第三次"为什么"还问得下去，说明前两层是表象，继续挖。
- 实在挖不出根因，诚实写"根因待查，xx 前给出结论"，不许编一个。

## 5. 对策怎么写

- **可行动**：有动作、有时间、有负责人。"优化一下"是愿望，"周二前改一版首屏布局（我负责）"是对策。
- **进下周计划**：对策必须在"下周计划"里有对应条目（SMART 化，见 lhg-wr-plan）。问题与对策两张皮，等于没写对策。
- **要支持的单独标**：需要老板/其他团队支持的，写"需要的支持：xxx"，别藏在对策里。

## 6. 本周真没问题？写风险前瞻

"问题与风险"写"无"是偷懒。真没问题，就写下周可能的风险：

```
风险前瞻：
- 双 11 主会场页面周五提测，设计稿周三才能定，存在延期风险；
  对策：已和设计约定周三上午过稿，留半天 buffer
```

**风险前瞻模板**：风险点 + 触发条件 + 应对预案。写 1~2 条即可。

## 7. 分级实战：一周的问题长什么样

```
🔴 现象：双 11 主会场页面设计稿延迟 2 天，开发排期被压缩到 3 天，
   存在延期风险
   根因：设计资源被临时抽去支援大促会场
   对策：已和设计约定周三上午过稿；开发侧先并行搭框架；
   需要的支持：请老板协调设计资源优先级

🟡 现象：联调环境本周阻塞 2 次共 6 小时
   根因：多团队共用一套环境，无独立 schema
   对策：周三前迁移独立 schema

🟢 现象：支付掉单客诉本周新增 3 起
   根因：幂等改造前的历史订单补偿缺失
   对策：已补发补偿并上线对账告警；结果：客诉清零
```

**分级纪律**：🔴 不超过 2 条（多了说明失控，要单独汇报不是写周报）；🟢 已解决的也要写（证明解题能力）；每条对策都要能在下周计划里找到对应条目。

## 8. 问题三段式速查卡

| 步骤 | 做什么 | 自查问题 |
|---|---|---|
| 写现象 | 数字/事实，可观测，可定位 | 用的是感受词吗？ |
| 挖根因 | 连问三次为什么 | 写成"人"的问题了吗？ |
| 配对策 | 动作+时间+负责人 | 能落进下周计划吗？ |
| 标分级 | 🔴≤2 条置顶 / 🟡可控 / 🟢已解决 | 🔴 超过 2 条了？ |
| 要支持 | 需要的支持单独列 | 藏在对策里了吗？ |

**新手最常犯的 3 个错**：① 只写现象（"联调 blocked"→然后呢？）；② 根因是"人"（"测试不配合"→改成流程问题）；③ 对策是愿望（"加强沟通"→改成动作+时间）。

## 9. 反模式

- ❌ "本周无问题"（然后下周暴雷）
- ❌ 只写现象（"联调 blocked"——然后呢？）
- ❌ 根因写成"人"的问题（"测试不配合"）
- ❌ 对策是愿望（"加强沟通""高度重视"）
- ❌ 对策没进下周计划（两张皮）
- ❌ 把"需要的支持"藏起来（老板不问你不说，问题就烂在你手里）

## 10. 常见问题

- **Q：问题是我老板造成的，能写吗？** A：能，但写法要变：现象照写，根因写成流程/机制问题（"审批链路长"而不是"老板批得慢"），对策写"我能做的部分"。周报是留档，不是檄文。
- **Q：根因涉及其他团队，会得罪人吗？** A：对事不对人：写"环境资源未独立"，不写"xx 团队占着不放"。同时先发给对方确认再进周报——这是职场基本礼仪。
- **Q：问题已经解决了，还写吗？** A：写，标🟢。解决的问题是"本周完成"之外的加分项，证明你有解题能力。写法：现象+根因+已采取的对策+结果。
- **Q：🔴 问题超过 2 个？** A：先保主线：只写阻塞主线的 2 个，其余的进"风险前瞻"或口头同步。周报里 5 个🔴等于告诉老板"这周失控了"。
- **Q：对策需要的时间超出下周？** A：拆成两步：下周能做的进下周计划（如"完成方案评审"），长期的写"中长期对策：xxx（预计 x 周）"。
- **Q：用户说"问题别写太细，怕老板觉得我不行"？** A：劝一次：老板怕的是"有问题不说"，不是"有问题"。藏问题+暴雷=信任清零。真敏感的，现象写粗一点，但对策必须有。

- **Q：风险前瞻写几条合适？** A：1~2 条。写多了等于"你觉得哪都是风险"，老板会免疫。只写"最可能发生、影响最大"的。
- **Q：对策写了但下周没资源做？** A：写"需要的支持"并标出来，同时给 Plan B："首选周三前迁移（需运维支持）；如支持不到位，Plan B 是错峰使用环境，阻塞时长预计降到 2 小时内"。有备选方案的问题才叫"预警过"。
- **Q：同一个问题连续三周都在，怎么写？** A：前面加"【持续】"标记，并升级对策："联调环境阻塞【持续 3 周】：前两周的临时方案（错峰使用）效果有限，本周升级为申请独立环境，周三前迁移"。老问题不升级对策，等于承认躺平。
- **Q：问题解决了但下周可能复发？** A：写两条：🟢 已解决（现象+根因+对策+结果）+ 🟡 复发风险（触发条件+预案）。解决是过去时，复发是将来时，都要交代。
- **Q：根因查到最后发现是"没资源"，怎么写？** A：写成资源缺口+申请："根因：测试人力不足（1 人支持 3 条业务线）；对策：已申请增加 1 名测试支持，周五前到位；过渡方案：核心链路优先回归"。要资源是正当的，藏着才是问题。
- **Q：问题涉及正在进行的敏感项目（如裁员、并购）？** A：周报里只写"受 xx 项目影响，…延期"，细节口头同步。书面留档的东西，默认会被转发。
- **Q：🟢 已解决的问题要写多细？** A：现象+根因一句话，对策+结果一句话。已解决的问题是加分项不是主角，别写成长篇。
- **Q：问题太多了，写不下？** A：按"影响主线"排序，只写前 3。其余的进"观察清单"一句话带过（"另有 2 个低优问题在跟进，无阻塞"）。周报不是问题全集。
- **Q：对策已经做了但没效果？** A：诚实写两轮："首轮对策（xx）效果不佳，根因重判为 xx；第二轮对策：xx，周五前验证"。对策迭代是正常的，藏着第一轮失败才奇怪。
## 11. 自检与反馈

**质检门**：
- [] 每个问题都有现象+根因+对策？
- [] 现象可观测（有数字/事实），不是感受？
- [] 根因是系统/流程问题，不是"人"的问题？
- [] 对策可行动（动作+时间+负责人），且进了下周计划？
- [] 需要的支持单独标出来了？

**标准冒烟用例**：取 2 个现象型记录（如"联调 blocked""转化率掉了"），用"三问为什么"挖根因并配对策，对照第 2 步检查。

**发现问题**：到本仓库提 issue（标题前缀 `[lhg-wr-issue]`），描述：场景、问题类型、哪一步不适用。
